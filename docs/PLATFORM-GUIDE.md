## Your 28 Questions

1. **What was removed from the hero?** The duplicate Lebanon map. The homepage now contains one map, in the Network section.
2. **What replaced it?** An animated PanoVision digital-display concept over the existing canopy visual. It has an eight-second visual timeline, a pause control and reduced-motion support. It is labelled as a concept, not an operational screen.
3. **How does the main map work?** It uses the project's real Lebanon boundaries and nine city coordinates. The accessible city list performs the same selections as the map markers.
4. **How does multi-selection work?** Selecting Beirut, Jounieh and Tripoli keeps all three. Clicking one again or removing its chip clears only that city. Clear selection removes all choices.
5. **How does zoom work?** Plus/minus change zoom from 1x to 4x. Enable the hand control for drag/pinch interaction. Reset returns to Lebanon without clearing selections. Normal page scrolling remains available when pan mode is off. Keyboard controls also work on the focused map.
6. **How will individual stations work?** Real configured stations appear as screen markers at closer zoom and as list choices. Selecting a station replaces its whole-city choice, preventing double selection. Screens from different cities can be combined.
7. **Where are real stations added?** `data/locations.ts`. Its `locations` array is intentionally empty. Use verified IDs, business names, city/region, coordinates, operating status, supported formats, dimensions and booking types. The old unused `locations.js` placeholder has been removed.
8. **How are estimates calculated?** `lib/pricing.ts` combines configured area/screen rates with inclusive days, rounded-up weeks or an exact special-event duration. Package and multi-location discounts use the larger applicable percentage, not stacked discounts. Missing rates, invalid dates, unknown inventory, overlapping city/screen selections or conflicting currencies produce a pending estimate, never a fabricated zero price.
9. **Where are prices entered?** Area rates, currency, packages and discount rules: `config/pricing.ts`. Individual screen rates: `data/locations.ts`. Special-event rates are keyed by the exact number of minutes. Estimates are not accepted quotes or availability guarantees.
10. **How do map selections transfer?** The Plan this campaign URL contains repeated `city` and `screen` parameters. The form validates and preselects them. Map preferences use tab session storage. A saved draft is associated with its originating plan so a refresh restores the draft without confusing a different new selection.
11. **How do accounts work?** Register through Log in > Create account. The existing SQLite backend now stores real customers and company memberships. Passwords use salted scrypt hashes. Sessions are server-side, expire and rotate at login/password changes; cookies are HttpOnly. Every campaign, report and private preview checks ownership on the server. Profile email changes require the current password plus one-use codes from both the current and new inbox, then revoke older sessions. SMTP must be configured before that flow is available.
12. **What information is collected?** Name, company, email, phone, optional country and role, language preference and a password hash. These are private, not public directory entries. This release registers one owner and company per customer account; inviting other company members is a future feature.
13. **How does the dashboard work?** It lists the signed-in company's actual stored campaigns and real status counts. New accounts show a genuine empty state. Campaign details show requested areas/screens/dates, creative status, eligible private media, quote if issued, payment/scheduling status and evidence if recorded. Creative approval is separate from commercial approval.
14. **How does Proof of Play work?** `proof_of_play` stores screen, campaign, creative version, actual time, optional play count, source, notes and verified reviewer. `proof_evidence` prepares private photo/video/log attachments. The customer view and JSON download include only recorded evidence. Requested dates never generate playback or audience numbers. The attachment-ingestion/admin workflow and PDF rendering are not yet connected.
15. **What must connect to real screens?** A player integration needs authenticated devices, immutable event IDs, replay protection, verified campaign/creative hashes, real timestamps, delivery acknowledgements and retention monitoring. It must obtain media through the existing verified publication gate. There is no public player endpoint in this release. See `docs/SCREEN-INTEGRATION.md`.
16. **How is WhatsApp configured?** Put the verified international number, including country code, into `company.whatsappNumber` in `lib/company.ts`. Leave it empty until verified. Invalid numbers produce no link. The helper strips permitted formatting and encodes the translated configurable message. No number was invented.
17. **Where was Instagram updated?** `lib/company.ts` now has `@PanoVisionlb` and `https://www.instagram.com/PanoVisionlb/`. Contact and footer read this shared configuration.
18. **Where was email updated?** The same configuration contains `panovision@gmail.com`, used by the contact page, email-app composer, footer and privacy/terms contact links.
19. **How do the languages work?** `next-intl`, `i18n/request.ts` and `messages/en.json`, `fr.json`, `ar.json`. The language selector stores a cookie; the account profile stores a preferred language. Customer pages, forms, messages, map controls, legal notices and metadata use shared translations. Staff moderation screens currently remain English.
20. **How does Arabic RTL work?** The document receives `lang="ar"` and `dir="rtl"`, with locally hosted Noto Sans Arabic. Layout uses logical spacing. Map geography is kept left-to-right so Lebanon is never mirrored. Emails, numeric technical values and playback controls preserve their appropriate direction.
21. **What Special Occasions section was added?** A prominent homepage section for birthdays, proposals, congratulations, openings, product launches, announcements, celebrations and custom messages. It links directly into the relevant campaign type.
22. **How do 5/10-minute bookings work?** Links preselect five or ten minutes. Custom duration accepts 1-1440 whole minutes. Occasion date and Beirut-local time are required. This requests display time; it does not guarantee a slot or take payment. Every creative still needs review.
23. **How do image previews work?** A temporary browser object URL displays the selected file without uploading it. Fit preserves the image; Fill can crop it. Dimensions and aspect-ratio warnings appear beside the preview. The URL is released when the file changes or the preview closes.
24. **How do video previews work?** Valid eight-second MP4/WebM files have play/pause/restart and mute controls. They start muted and do not automatically play loud audio. Actual duration, dimensions and format are shown. Uploading for moderation remains a separate action.
25. **How do screen-specific previews work?** Configured width/height, or aspect ratio, determines the display shape, including portrait orientation. When several screens are selected, a selector switches the preview. With no real screen, the interface explicitly shows a concept display and pending location requirements.
26. **What needs configuration before production?** Inventory, rates, currency, supported screen specs, admin accounts, maintained media tools, malware scanner, moderation credentials, persistent hosting, HTTPS/domain, backups, retention procedures, email service and professionally reviewed legal documents. Paid delivery additionally needs a payment/ledger workflow and actual screen integration. Local preview success is not live-service certification.
27. **Which credentials/environment variables are needed?** Account login itself needs no new SaaS credential. Staff accounts are created privately using `scripts/admin-create.ts`, never a default password. Production settings are documented in `.env.example` and `docs/PRODUCTION.md`: notably `PANO_APP_ORIGIN`, `PANO_PRIVATE_DIR`, `PANO_UPLOADS_ENABLED`, `MODERATION_PROVIDER`, `MODERATION_API_KEY`, `FFMPEG_PATH`, `FFPROBE_PATH`, `CLAMSCAN_PATH` and `NEXT_PUBLIC_SITE_URL`. Email changes additionally need `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD` and a provider-verified `SMTP_FROM`. Do not put secrets in `NEXT_PUBLIC_*` variables or share `.env.local`/`.private`.
28. **What should you do next?** Open the local site and create your own customer account. Try three city selections, a special occasion and a harmless local preview. Supply verified station details, the intended currency/rates and a real WhatsApp number when available. Ask your deployment operator to follow `docs/PRODUCTION.md` for scanner/provider setup and staff provisioning. Complete email/payment/player integrations and operational/legal review before inviting real paying customers. Missing services must never be bypassed just to show an approved result.

## Data And Operations

The additive account/report migration is `lib/server/customer-schema.ts`. Existing campaigns, assets, moderation evidence and audit history are retained. Pre-account anonymous sessions are not silently assigned to newly registered accounts: a trusted operator must verify ownership before any deliberate migration. A consistent SQLite backup was created inside `.private` before starting the updated main app. Keep that directory private.

The current implementation is a single-host Node 24 / Next.js service with SQLite WAL and a separate moderation worker. Both must use the same persistent private storage and configuration. Do not deploy the authenticated backend as a static site or on ephemeral/serverless storage. The separate public preview has not been changed by this update.
